Создай полноценный production-ready лендинг BURGER HOUSE на основе дизайна из Google Stitch.

Используй подключённый Stitch MCP как основной источник правды по дизайну.

────────────────────────────────────
ГЛАВНАЯ ЗАДАЧА
────────────────────────────────────

1. Найди в Stitch проект BURGER HOUSE.
2. Изучи все созданные экраны и секции.
3. Получи доступные:
   - изображения;
   - тексты;
   - цвета;
   - шрифты;
   - размеры;
   - сетку;
   - отступы;
   - декоративные элементы;
   - адаптивные варианты.
4. Реализуй весь лендинг от header до footer.
5. Максимально точно повтори дизайн Stitch.

Не придумывай новый дизайн.
Не упрощай композиции.
Не превращай сайт в стандартный шаблон ресторана.

────────────────────────────────────
ТЕХНОЛОГИИ
────────────────────────────────────

Используй:

- pnpm
- Next.js с App Router
- React
- TypeScript в strict-режиме
- Tailwind CSS
- next/image
- Lucide React
- Framer Motion для лёгких анимаций
- ESLint
- Playwright для визуальной проверки

Не используй:

- npm или yarn;
- Redux;
- тяжёлые UI-библиотеки;
- отдельный backend;
- базу данных;
- Three.js и 3D-модель на этом этапе;
- лишние зависимости.

Основной бургер в hero пока должен быть обычным качественным изображением.

Перед установкой зависимости проверь, действительно ли она нужна и не установлена ли уже.

Все команды запускай через pnpm:

pnpm install
pnpm lint
pnpm typecheck
pnpm build
pnpm dev

Если скрипта typecheck нет, добавь:

" typecheck": "tsc --noEmit"

без пробела перед названием ключа.

────────────────────────────────────
ПЕРЕД НАЧАЛОМ
────────────────────────────────────

Сначала:

1. Изучи текущую структуру репозитория.
2. Проверь package.json и существующие зависимости.
3. Не перезаписывай готовые настройки без необходимости.
4. Изучи все секции BURGER HOUSE через Stitch MCP.
5. Сопоставь порядок экранов Stitch с итоговой страницей.
6. Определи повторяющиеся компоненты.
7. Составь короткий план реализации.
8. Только после этого начинай менять файлы.

Если проект пустой, настрой Next.js-проект в текущей директории с использованием pnpm, TypeScript, Tailwind CSS, App Router и ESLint.

Не создавай вложенный второй проект внутри текущей папки.

View full menu

Баннер должен включать:

- Buy any burger, get one FREE!;
- Order now;
- два бургера;

Используй next/image.

Сохрани правильное соотношение сторон.

Если текст внутри изображения становится нечитаемым на маленьком экране, используй отдельный мобильный banner asset из Stitch. Если его нет, добавь адаптивный контейнер с горизонтально безопасным масштабированием без изменения дизайна desktop.

────────────────────────────────────
КОМПОНЕНТНАЯ АРХИТЕКТУРА
────────────────────────────────────

Используй понятную структуру компонентов, например:

src/
├── app/
│   ├── layout.tsx
│   ├── page.tsx
│   └── globals.css
├── components/
│   ├── layout/
│   │   ├── Header.tsx
│   │   └── Footer.tsx
│   ├── sections/
│   │   ├── HeroSection.tsx
│   │   ├── FeaturedFavorites.tsx
│   │   ├── PromoSection.tsx
│   │   ├── BenefitsSection.tsx
│   │   └── FinalCtaSection.tsx
│   └── ui/
│       ├── Button.tsx
│       ├── BurgerCard.tsx
│       ├── CategoryFilter.tsx
│       ├── BenefitItem.tsx
│       └── SectionHeading.tsx
├── data/
│   └── burgers.ts
├── lib/
│   └── utils.ts
└── types/
    └── index.ts

Можно адаптировать структуру под существующий репозиторий.

Не создавай:

- один огромный page.tsx;
- ненужные глобальные состояния;
- prop drilling через множество уровней;
- чрезмерно универсальные компоненты;
- компоненты ради одной строки разметки.

Используй Server Components по умолчанию.

Добавляй "use client" только компонентам, которым реально нужны:

- state;
- обработчики;
- Framer Motion;
- мобильное меню;
- фильтры;
- корзина.

────────────────────────────────────
ИЗОБРАЖЕНИЯ
────────────────────────────────────

Получай изображения из Stitch, когда они доступны.

Сохраняй их локально:

public/
├── images/
│   ├── hero/
│   ├── burgers/
│   ├── banners/
│   ├── avatars/
│   └── brand/
└── icons/

Используй:

- next/image;
- корректные width и height;
- sizes;
- object-fit;
- object-position;
- priority только для hero;
- lazy loading для остальных секций.

Не используй случайные внешние URL.

Не используй screenshot всей страницы как фон.

Не растягивай изображения.

Не ухудшай их пропорции.

Если Stitch предоставляет цельный promo или CTA banner, сохрани его отдельным файлом и используй только в соответствующей секции.

────────────────────────────────────
СТИЛИ
────────────────────────────────────

Используй Tailwind CSS.

Вынеси основные дизайн-токены в CSS variables:

- background;
- foreground;
- yellow;
- red;
- cream;
- charcoal;
- border radius;
- container width.

Основной desktop viewport:

1440 px

Основной контейнер:

1280 px

Горизонтальные поля:

80 px на desktop с адаптивным уменьшением.

Сохрани:

- яркий жёлтый фон;
- красные акценты;
- кремовые поверхности;
- чёрную типографику;
- крупный condensed display font;
- закруглённые карточки;
- мягкие тени;
- декоративные doodles;
- энергичный fast-food стиль.

Не добавляй:

- glassmorphism;
- фиолетовые градиенты;
- неон;
- тёмный hero;
- стандартную серую SaaS-стилистику.

────────────────────────────────────
АНИМАЦИИ
────────────────────────────────────

Используй Framer Motion умеренно.

Добавь:

- появление строк hero-заголовка с небольшим stagger;
- лёгкое вертикальное движение изображения бургера;
- мягкий parallax для помидора, салата и doodles;
- небольшую пульсацию скидочного badge;
- hover lift для кнопок;
- движение стрелки внутри кнопки;
- появление секций при скролле;
- hover lift карточек меню;
- zoom изображения внутри карточки;
- анимацию кнопки добавления;
- плавное переключение фильтров;
- мягкое появление promo и CTA;
- sticky-анимацию header.

Не делай:

- агрессивные вращения;
- бесконечные быстрые движения;
- сложные scroll-сцены;
- 3D;
- анимации, мешающие чтению.

Обязательно учитывай prefers-reduced-motion.

────────────────────────────────────
АДАПТИВНОСТЬ
────────────────────────────────────

Обязательно проверь:

- 1440 px;
- 1280 px;
- 1024 px;
- 768 px;
- 390 px.

Desktop:

- максимально точно повторить Stitch;
- четыре карточки меню в одной строке.

Tablet:

- header перестраивается;
- меню сворачивается при нехватке места;
- hero сохраняет визуальный приоритет бургера;
- карточки меню идут по две в ряд;
- преимущества идут по две колонки.

Mobile:

- компактный header;
- burger menu;
- hero-текст сверху;
- изображение бургера ниже;
- кнопки складываются при необходимости;
- все декоративные элементы остаются внутри viewport;
- карточки показываются по одной или горизонтальным slider;
- преимущества идут в одну колонку;
- footer идёт в одну колонку;
- баннеры не создают overflow;
- важный текст не обрезается.

Не просто уменьшай desktop пропорционально.

Осмысленно перестраивай композицию.

Минимальная область нажатия:

44 × 44 px.

ИНТЕРАКТИВНОСТЬ
────────────────────────────────────

Реализуй:

- рабочую якорную навигацию;
- мобильное меню;
- category filters;
- добавление товара в локальную корзину;

Кнопки Order now могут вести к секции меню или открывать подготовленный mock order panel, но не должны вести на несуществующую страницу.

ДОСТУПНОСТЬ
────────────────────────────────────

Используй semantic HTML:

- header;
- nav;
- main;
- section;
- article;

Добавь:

────────────────────────────────────
ПРОВЕРКА ЧЕРЕЗ PLAYWRIGHT
────────────────────────────────────

После реализации:

1. Запусти pnpm lint.
2. Запусти pnpm typecheck.
3. Запусти pnpm build.
4. Исправь все ошибки.
5. Запусти сайт локально.
6. Используй Playwright MCP.
7. Сделай full-page screenshots на:
   - 1440 px;
   - 1024 px;
   - 768 px;
   - 390 px.
8. Сравни реализацию с дизайном Stitch.
9. Исправь объективные визуальные расхождения.
10. Повтори проверки.

Особенно проверь:

- ширину контейнера;
- высоту hero;
- размеры заголовка;
- положение бургера;
- banner assets;
- четыре карточки меню в desktop-строке;
- волнистые разделители;
- вертикальные отступы;
- mobile navigation;
- фильтры;
- корзину;
- горизонтальный overflow;
- console errors;
- layout shift;
- работу всех кнопок.

Не останавливайся после первой рабочей версии.

Проведи минимум один дополнительный проход визуальных исправлений после Playwright screenshots.
